# Motion Reel

You make a short looping video about an idea, entirely in code. A reel is one small JavaScript file:
a list of scenes on a beat grid, each scene one technique with the idea's own words, shapes, colours
and moves, joined by transitions. The engine draws every frame as a function of time, so the reel
renders frame by frame with motion blur, cuts land on the beat, and the last frame flows into the
first. Nothing is photographed or generated by a model: it suits abstract ideas best.

`<skill>` below means this skill's folder: the folder this `SKILL.md` is in.

## What you need

| Need | Why | How |
| --- | --- | --- |
| The idea | what the reel is about, and its name for the end card | what the user said: `/motion-reel entropy` in Claude Code, `$motion-reel a reel about momentum` in Codex, or "make a looping motion reel about …" |
| Node 18+ | the scripts | `node -v` |
| Chrome or Edge | draws the frames, headless | an installed Chrome or Edge; otherwise `npx playwright install chromium` |
| ffmpeg | the MP4 and the sound | `ffmpeg -version`; install with `brew install ffmpeg`, `winget install Gyan.FFmpeg` or `apt install ffmpeg` |

No credits and no API keys: everything is drawn in code, fonts included. The first run installs
`playwright-core` once from npm into a cache folder (never into the project) and drives the
installed browser.

## Steps

1. **Find the idea's arc** (`references/writing.md`). In a few lines: what the idea is, what turns
   into what over the reel (order → noise, small → endless, up → down), and which structure carries
   it. Four come ready: **rewind** (it breaks down, then the whole reel rewinds to its start),
   **zoom** (every cut dives into the scene before), **fall** (every cut drops into the next),
   **montage** (a showreel of techniques). Then cast the scenes, write the words, pick the look.
   Ask only for what you can't invent: the name, and facts or numbers if the reel shows any.
2. **Start the reel**: `node <skill>/scripts/new.mjs <name> --from rewind` (or `zoom`, `fall`,
   `montage`) writes `./<name>/reel.js`. `--from entropy | infinity | gravity` starts from one of
   the finished examples instead; their words are theirs, so rewrite all of them.
3. **Make it the idea's own.** Replace every `«…»`: the words, labels and readouts, the 3D forms and
   their moves, the shapes, the palette, the fonts, the energy. Reorder, drop or repeat scenes as the
   arc needs. `references/scenes.md` has every scene and option, `references/transitions.md` every
   join, `references/craft.md` the rules that keep it working (bars, pace, the loop, energy, type).
4. **Check**: `node <skill>/scripts/check.mjs <name>/reel.js`. It prints a line per check and writes
   `<name>/<name>-check.png`: every scene at three moments and the frames around the loop. Read the
   PNG. Fix every FAIL and WARN, then look: does every word read, does each scene act out its step of
   the arc, does the loop strip flow? `node <skill>/scripts/frames.mjs <name>/reel.js --scene 3 --n 12`
   shows one scene closely. This works without a browser window: it all runs headless.
5. **Look at it moving** (when there is a browser or a preview tool): `node <skill>/scripts/build.mjs
   <name>/reel.js` writes `<name>/<name>.html`; open it (space plays and pauses, arrows step a frame,
   shift+arrows a beat). Without a browser, run `make.mjs --draft` in step 6 first and check the frames
   it writes instead.
6. **Render**: `node <skill>/scripts/make.mjs <name>/reel.js` writes the page, the soundtrack
   (`out/<name>.wav`, exactly one loop) and `out/<name>-9x16.mp4`, rendered frame by frame. Add
   `--format 9x16,1x1` for more formats, `--draft` for a quick half-size look first, `--audio
   song.mp3 --at 12` for their own track (`references/audio.md`). The full render takes a few minutes.
7. **Hand over** the MP4s and the folder. Say in a few lines: the arc, the structure, the scenes and
   what each shows, the palette and tempo, what you chose without asking, anything you couldn't
   check. `node <skill>/scripts/share.mjs <name>/out/<name>-9x16.mp4 --mb 25` makes a copy small
   enough for a chat app or an email.

## Rules

| If you catch yourself | Do this instead |
| --- | --- |
| copying an example's words or arc | the idea's own; the examples show how, not what |
| inventing a statistic or a fact about the subject | a real one from the user, or a number true of the reel itself (frames, fps, beats) |
| `EVERY / SINGLE / …` or any stock phrase | words only this idea would say |
| text under 20 px, or text crossing the busiest part of a scene | the engine keeps labels at 20 px (`minText`); keep big words where they read |
| beats that don't add up to whole bars of 4 | lengthen or shorten a scene; `check.mjs` fails otherwise |
| a scene under 2 s, a burst shot under 1 s | more `beats` (or `per`), then `slow` |
| four kinds of transition in one reel | two or three, repeated: that reads as a style |
| more than three full-frame flashes in a second | fewer hits; `energy` lower |
| editing `<skill>/assets/engine/` | an option, a palette, or a scene or transition of your own in the reel file (`references/custom.md`) |
| `Math.random()` or a timer in your own scene | `g.rng(seed)`, `g.hash(i)`, everything from `t.b` |
| a loop that jumps | the last scene's `out` opens onto the first frame, or a rewind lands on it; the first scene starts calm |
